# Prompt: รวมกลุ่มที่ความหมายซ้ำ (topic merge)

> **สถานะ: ออกแบบไว้ล่วงหน้า — ยังไม่ implement** (`config.yaml` มี `labeling.merge_duplicates: true` แต่โค้ดยังไม่มีขั้น merge; ดู ROADMAP)
> เมื่อ implement: แนะนำวางเป็น step ย่อยท้าย `label.py` เฉพาะระดับ coarse แล้วเขียนผล mapping ลง `work/05_merges.parquet`

## บริบทการใช้

HDBSCAN บางครั้งแยกกลุ่มที่ความหมายเดียวกันออกเป็นหลายกลุ่ม (เช่น "การศึกษาพยาบาล" กับ "นิสิตพยาบาล")
ขั้นนี้ส่งรายชื่อกลุ่ม (ระดับ coarse) ทั้งหมดให้ LLM ชี้คู่/กลุ่มที่ควรรวม

## Prompt (master)

```
คุณคือผู้เชี่ยวชาญด้านการจัดหมวดหมู่งานวิจัย ด้านล่างคือรายการกลุ่มหัวข้อวิจัยที่ระบบจัดอัตโนมัติ
บางกลุ่มอาจมีความหมายซ้ำกัน (ต่างกันแค่มุมมองหรือคำเรียก)

รายการกลุ่ม:
{group_list}

งานของคุณ: ระบุกลุ่มที่ควร "รวมเป็นกลุ่มเดียวกัน" เท่านั้น (ถ้าไม่มี ให้ตอบ merges ว่าง)

เกณฑ์:
- รวมเฉพาะกรณีที่เนื้อหางานวิจัยเหมือนกันมาก (≥80% ทับซ้อนเชิงความหมาย)
- ห้ามรวมกลุ่มที่ต่างสาขาชัดเจน แม้ใช้เครื่องมือ/วิธีคล้ายกัน
- ชื่อกลุ่มรวมต้องเป็นภาษาไทยที่บรรณาธิการวารสารใช้จริง

ตอบกลับเป็น JSON เท่านั้น:
{
  "merges": [
    {
      "ids": ["g3", "g7"],
      "merged_name_th": "ชื่อกลุ่มรวม",
      "merged_name_en": "Merged group name",
      "reason": "เหตุผล 1 บรรทัด"
    }
  ]
}
```

## หมายเหตุการ implement

- ส่งเฉพาะระดับ **coarse** (จำนวนน้อย 10–30 กลุ่ม → 1 API call) ไม่ต้อง merge ระดับ fine
- ผล merge ควรเป็น "แนะนำ" ให้คนตรวจก่อน apply (เขียน `05_merges.parquet` แล้วให้ flag `approved`)
- อย่า merge อัตโนมัติโดยไม่มีคนดู — กลุ่มที่รวมผิดทำแผนที่เพี้ยนทั้งใบ
