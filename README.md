# TCI Research Atlas

**แผนที่ภูมิทัศน์งานวิจัยไทย** — เครื่องมือ discovery & insight จากบทความวารสารวิชาการไทย (TCI/ThaiJO)
สำหรับ **นักวิจัย** (หาช่องว่าง ดูหัวข้อกำลังโต) · **บรรณาธิการ** (เห็นภาพรวมสาขา) · **ผู้บริหาร** (dashboard เพื่อนโยบาย)

## ระบบประกอบด้วย 2 ส่วน

```
┌─────────────────────────────┐         ┌──────────────────────────────┐
│  pipeline/  (Python batch)  │         │  web/  (React dashboard)     │
│  รันทุก 3 เดือน             │  JSON   │  เว็บ v2 อ่าน                │
│                             │ ──────► │  data/latest.json →          │
│  คลัง .md จาก ThaiJO        │         │  data/<release>/             │
│  → embed → cluster → label  │         │  (ไม่มีข้อมูลสำรองฝังในเว็บ) │
│  → emerging → forecast      │         │  overview · atlas · topic ·  │
│  → data/<release>/          │         │  emerging · compare · brief  │
└─────────────────────────────┘         └──────────────────────────────┘
```

- **ไม่มีฐานข้อมูล ไม่มี backend** — เว็บเป็น static site ที่อ่าน JSON ของรอบล่าสุดตอนเปิดหน้า
- **อัปเดตข้อมูล = `uv run atlas publish --site web/dist` (หรือคัดลอกโฟลเดอร์ `data/` ใหม่) — ไม่ต้อง build เว็บใหม่**

## Quick start

```bash
cd pipeline
uv sync --extra local                      # หรือ --extra api
cp config.example.yaml config.yaml         # แก้ input.path → โฟลเดอร์คลัง (รูปแบบ 1.0: docs/corpus/README.md)
export ATLAS_EMBED_API_KEY=...             # ถ้าใช้ embedding แบบ API
export ATLAS_LLM_API_KEY=...               # ถ้าใช้ LLM (ชื่อหัวข้อ/คำอธิบาย/บทสรุป) — ใช้ key เดียวกันได้
uv run atlas quarterly --corpus /path/to/corpus --release 2026Q4   # รอบไตรมาสครบในคำสั่งเดียว → deploy/2026Q4/site พร้อมอัปโหลด
uv run pytest -q                           # ทดสอบ pipeline
cd ../web && npm run dev                   # ดูผลที่ localhost
```

ข้อมูลจริง (คลังบทความ, รอบข้อมูลจริง) **ไม่เข้า git** — repo เก็บเฉพาะตัวอย่าง 11 ไฟล์ใน `pipeline/tests/fixtures/` และรอบข้อมูลสังเคราะห์ใน `web/fixtures/`

คู่มือนักศึกษาฝึกงาน (เตรียมคลัง → รัน → เปิดเว็บสาธารณะ): `docs/INTERN_GUIDE.md` · รอบรันจริงรายไตรมาส (step-by-step): `docs/OPERATIONS.md` §1 · เตรียมคลังบทความ: `docs/corpus/README.md` · สเปกข้อมูล: `docs/DATA_SPEC.md` · นิยาม emerging: `docs/EMERGING_SPEC.md` · แผนหลัก v2: `docs/superpowers/specs/2026-10-18-tci-atlas-v2-design.md`

## นิยาม "Emerging" ของ TCI v3 (ย่อ)

หน้าต่างเวลา: **R = 3 ปีล่าสุดที่สมบูรณ์**, **B = 5 ปีก่อนหน้า R** (ไม่นับปีที่กำลังดำเนินอยู่ และตัดปีที่ข้อมูลยัง backfill ไม่เสร็จออกอัตโนมัติ) · สถานะใช้ช่วงเชื่อมั่นของการเติบโต ไม่ใช่ค่าจุดเดียว

| สถานะ | ความหมาย (ดีฟอลต์) |
|---|---|
| **LOW_DATA** ข้อมูลน้อย | count_R < 30 หรือประมาณ share_growth ไม่ได้ — ไม่ฟันธง |
| **EMERGING** กำลังเกิดใหม่ | หัวข้อเล็ก **และ** ขอบล่างของช่วงเชื่อมั่นการโต ≥ +10%/ปี **และ** share_ratio ≥ 1.8 **และ** ความกว้าง (วารสาร/สถาบัน) ผ่าน |
| **WATCH** จับตา | โตตามเกณฑ์ EMERGING แต่ความกว้างไม่ผ่าน (สัญญาณ journal-entry bias) |
| **HOT** กำลังมาแรง | หัวข้อใหญ่ **และ** ขอบล่างของช่วงเชื่อมั่นการโต > 0 |
| **DECLINING** ลดลง | ขอบบนของช่วงเชื่อมั่นการโต < 0 **และ** share_ratio ≤ 0.8 |
| **STABLE** คงที่ | อื่น ๆ |

สถานะตรวจตามลำดับข้างต้น (ข้อแรกที่เข้าคือคำตอบ) · Emerging Score 0–100 เป็น percentile ภายในรอบ ใช้จัดอันดับเท่านั้น เทียบข้ามรอบไม่ได้
สเปกเต็มพร้อมสูตรและเหตุผลเชิงวิธีวิจัย: `docs/EMERGING_SPEC.md`

## Forecasting

ทำนายจำนวนบทความรายปีของแต่ละหัวข้อล่วงหน้า 2 ปี ด้วย naive / linear (OLS) / Poisson GLM — เลือกโมเดลต่อหัวข้อด้วย backtest และแสดงผล **เฉพาะหัวข้อที่ผ่าน skill gate** (แม่นกว่า naive); หัวข้อที่ไม่ผ่านจะไม่มีเส้นทำนายใน JSON (`forecast: null`, `forecast_uncertain: true`)

## P1 (analytics v2)

หัวข้อมี ID ถาวรข้ามไตรมาส, กลุ่มใหญ่ตาม OpenAlex fields, พยากรณ์พร้อมช่วง 80/95% และ nowcast ของปีที่ยังไม่ครบ, emerging keywords, คำอธิบายหัวข้อและบทสรุปผู้บริหารที่ตัวเลขทุกตัวมาจาก pipeline, และการเผยแพร่แบบ static (`atlas publish --site` → `data/latest.json` + ไฟล์ HTML เดี่ยวสำหรับ offline) — ดู `docs/OPERATIONS.md`

## P4 — รุ่นนักวิจัย

หน้าใหม่ (lazy) ในเมนู "หางานวิจัย", "อะไรกำลังมา" และ "ใครทำเรื่องอะไร": `#/search` ค้นหาบทความทั้งคลังจากชื่อเรื่องและคำสำคัญ (ไทย/อังกฤษ, กรองปี/หัวข้อ/วารสาร, ส่งออก CSV · RIS · BibTeX) · `#/galaxy` แผนที่บทความทุกเรื่อง (เดิมชื่อ "กาแล็กซีบทความ": ทุกบทความเป็นจุดบนแผนที่ WebGL2 คลิกเพื่อดูบทความ) · `#/keywords` แนวโน้มคำสำคัญของผู้แต่ง (เทียบได้ครั้งละ 4 คำ) + อภิธานศัพท์ไทย↔อังกฤษ · `#/references` แนวปฏิบัติการอ้างอิงรายวารสารและบทความที่ "ถูกอ้างใน TCI" (แสดงเมื่อคลังมีรายการอ้างอิงมากพอ ไม่งั้นหน้าบอกเหตุผล) · หน้าหัวข้อเพิ่มอภิธานศัพท์ ตัวเลขถูกอ้างใน TCI ชิป SDG และปุ่ม RIS/BibTeX · กราฟฝังเว็บอื่นได้ (`#/embed/topic/:id`, `#/embed/emerging`) · "อ้างอิง Atlas นี้" ใน `#/about` + `CITATION.cff` · ฟีด Atom ต่อรอบและต่อหัวข้อเมื่อตั้ง `publish.site_url` — ไม่มีชื่อผู้แต่งหรือบทคัดย่อในไฟล์ใด ดัชนีค้นหาและกาแล็กซีไม่อยู่ในไฟล์ออฟไลน์ · ตั้งค่าและขั้นตอน: `docs/OPERATIONS.md` §17–§20

## P3 — รุ่นผู้บริหาร

เมนูแบ่งเป็น 3 กลุ่ม (สำหรับผู้บริหาร / บรรณาธิการ / นักวิจัย) และหน้าใหม่ 6 หน้า (lazy): `#/institutions` + `#/institutions/:id` สถาบัน (ผลงาน สัดส่วนร่วมกับต่างประเทศ คู่ความร่วมมือ ประเทศคู่ความร่วมมือ สถาบันที่อาจร่วมงานได้ — ระดับสถาบันเท่านั้น ไม่มีข้อมูลรายบุคคล) · `#/regions` แผนที่จังหวัด (บทความรายจังหวัด/ภาค มีมุมมองตาราง) · `#/sdg` SDG + BCG + แผนด้าน ววน. + หมุดหมายแผนฯ 13 · `#/global` ไทยเทียบโลกราย subfield ของ OpenAlex · `#/gaps` โอกาสที่ยังไม่มีใครทำ (เดิมชื่อ "ช่องว่างงานวิจัย": ช่องว่างงานวิจัยและความเสี่ยงกระจุกตัว) · ภาพรวมและ brief มีประโยคเชิงนโยบาย (แม่แบบ ไม่ใช้ LLM) · ตั้งค่าและขั้นตอน: `docs/OPERATIONS.md` §13–§16

## P2 — รุ่นบรรณาธิการ

หน้าเว็บเพิ่ม 5 หน้า (โหลดแบบ lazy): `#/journals` ตัวชี้วัดวารสาร (ความครบถ้วน metadata, สัดส่วนผู้แต่งในสถาบันเจ้าของ, ความหลากหลายสถาบัน, หัวข้อโอกาสฉบับพิเศษ) · `#/journals/:id` โปรไฟล์วารสาร · `#/methods` วิธีวิจัยรายหัวข้อและรายปี (+ วิธีกระจุก) · `#/changes` อะไรเปลี่ยนจากรอบก่อน (รวม/แยก/ยุติหัวข้อ) · `#/match` วางบทคัดย่อเพื่อหาหัวข้อที่ใกล้ที่สุดและวารสารที่ควรส่ง — คำนวณในเบราว์เซอร์ ข้อความไม่ถูกส่งไปที่ใด ชื่อวารสารเต็ม/ISSN/กลุ่ม TCI ใส่ได้ผ่าน `pipeline/registry/journals.csv` (ดู `docs/OPERATIONS.md` §10) ตัวชี้วัดทั้งหมดเป็นยอดรวม ไม่มีข้อมูลระดับบุคคล
