# TCI Research Atlas

**แผนที่ภูมิทัศน์งานวิจัยไทย** — เว็บที่บอกว่างานวิจัยไทยเรื่องไหนกำลังมา เรื่องไหนลดลง ใครทำเรื่องอะไร และไทยอยู่ตรงไหนเมื่อเทียบกับโลก โดยวิเคราะห์จากบทความในวารสารไทยที่อยู่ในฐาน TCI/ThaiJO และอัปเดตทุก 3 เดือน

ทำมาเพื่อคน 3 กลุ่ม:

- **นักวิจัยและนักศึกษา** — หาหัวข้อที่กำลังโตหรือยังมีคนทำน้อย และดูว่าวารสารไหนลงเรื่องใกล้งานของตัวเอง
- **บรรณาธิการวารสาร** — ดูว่าวารสารของตัวเองลงเรื่องอะไร เทียบกับสาขา และวางแผนฉบับพิเศษ
- **ผู้บริหารและฝ่ายนโยบาย** — ดูภาพรวมของประเทศ รายจังหวัด รายสถาบัน และเป้าหมาย SDG ในหน้าเดียว

## ระบบทำงานอย่างไร

```
คลังบทความ (รูปแบบ 1.0)      pipeline/ (Python)                       web/ (React)
articles/*.jsonl.gz      ──►  ตรวจคลัง → จัดกลุ่มหัวข้อ → หาแนวโน้ม  ──►  เว็บ static อ่าน
journals.csv  ฯลฯ             → ตรวจรอบ + ตรวจข้อมูลส่วนบุคคล             data/latest.json
                              → data/<รอบ>/*.json                     → data/<รอบ>/*.json
                              → deploy/<รอบ>/site/ พร้อมอัปโหลด
```

- **ไม่มีฐานข้อมูล ไม่มีเซิร์ฟเวอร์โปรแกรม** — เว็บเป็นไฟล์ static วางบน host ใดก็ได้ (IIS, Apache, Nginx, S3, GitHub Pages) และอ่านข้อมูลรอบล่าสุดตอนเปิดหน้า
- **อัปเดตข้อมูลไม่ต้อง build เว็บใหม่** — แค่วางโฟลเดอร์ `data/` ของรอบใหม่ขึ้น host
- มีไฟล์ `atlas-offline.html` ไฟล์เดียว เปิดดูได้โดยไม่ต่ออินเทอร์เน็ต
- `atlas quarterly` และ `atlas publish` ไม่อัปโหลดอะไรเอง คนเป็นผู้อัปโหลดหลังตรวจผลแล้ว

## รอบรายไตรมาสด้วยคำสั่งเดียว

ติดตั้งครั้งแรก (รายละเอียดใน `docs/OPERATIONS.md` §0):

```bash
cd pipeline
uv sync --extra api                     # embedding ผ่าน API — หรือ --extra local ถ้ามี GPU
cp config.example.yaml config.yaml      # แก้ input.path, state_dir, embedding, LLM, publish.site_url
```

API key ใส่ใน env var เท่านั้น ห้ามเขียนลงไฟล์: `ATLAS_EMBED_API_KEY` (embedding), `ATLAS_LLM_API_KEY` (LLM — ใช้ key เดียวกันได้), `OPENALEX_API_KEY` (ไม่บังคับ)

ทุกไตรมาส:

```bash
cd pipeline
uv run atlas quarterly --corpus D:/atlas-data/corpus/2026Q4 --release 2026Q4 --prepare   # ตรวจคลังก่อน (ไม่เสียเงิน)
uv run atlas quarterly --corpus D:/atlas-data/corpus/2026Q4 --release 2026Q4             # ทั้งรอบ
```

- บน Windows ดับเบิลคลิก `scripts\quarterly_run.cmd` ได้เลย (ใช้ `input.path` ใน config และไตรมาสของวันนี้) — บน Linux/cron ใช้ `bash scripts/quarterly_run.sh` ตัวเลือกเดียวกัน
- ก่อนจ่ายค่า LLM ระบบแสดงค่าใช้จ่ายโดยประมาณและถามยืนยันก่อนทุกครั้ง (ข้ามได้ด้วย `--yes`)
- หยุดกลางทาง = แก้ตามข้อความที่ขึ้น แล้วสั่งคำสั่งเดิมอีกครั้ง ส่วนที่จ่ายเงินไปแล้วไม่ถูกจ่ายซ้ำ
- **ผลที่ได้:**
  - `runs/<รอบ>/` — บันทึกของรอบ: config ที่ใช้จริง รายการไฟล์คลัง รายงานตรวจคลัง log ผลตรวจ และ `summary.md` ที่บอกว่าต้องอัปโหลดอะไรไปที่ไหน
  - `deploy/<รอบ>/site/` + `deploy/atlas-site-<รอบ>.zip` (ทั้งเว็บ) + `deploy/atlas-data-<รอบ>.zip` (เฉพาะข้อมูล สำหรับรอบถัดไป)
  - ทั้งสองโฟลเดอร์อยู่ที่รากของ repo และไม่เข้า git
- embedding ครั้งใหญ่ครั้งแรก การตรวจผลก่อนเผยแพร่ การตรวจชื่อหัวข้อ และการขึ้นเว็บ: ดู `docs/OPERATIONS.md` §1

## เตรียมคลังบทความ

คลังที่แนะนำคือ **รูปแบบ 1.0 (JSON Lines)**: โฟลเดอร์ `articles/*.jsonl.gz` (1 บรรทัด = 1 บทความ) พร้อมไฟล์ประกอบ

| ไฟล์ | จำเป็นไหม |
|---|---|
| `journals.csv` — 1 แถวต่อวารสาร | บังคับ |
| `institutions_aliases.csv` — ชื่อสถาบันที่เขียนต่างกัน → สถาบันเดียว | แนะนำมาก |
| `province_population.csv` — ประชากร 77 จังหวัด (แม่แบบ: `docs/corpus/province_population.template.csv`) | แนะนำ |
| `ror.zip` — ฐานข้อมูลสถาบัน ROR | ไม่บังคับ |
| `README.txt` — บันทึกที่มาข้อมูลและการตัดสินใจ | บังคับ |

เมื่อรันด้วย `atlas quarterly` ไฟล์ประกอบที่วางในโฟลเดอร์คลังจะถูกใช้แทนค่าใน `config.yaml` โดยอัตโนมัติ

ตรวจไฟล์เองก่อนส่ง:

```bash
# ตรวจละเอียด รวมไฟล์ประกอบ (exit 1 = ต้องแก้) — รันใน pipeline/
uv run atlas profile /path/to/corpus --md profile.md
# ตรวจแบบเบา ไม่ต้องติดตั้ง Atlas — รันจากรากของ repo (ต้อง pip install jsonschema ก่อน)
python docs/corpus/validate_jsonl.py /path/to/corpus
```

คลังเดิมที่เป็นไฟล์ `.md` ของ ThaiJO ยังใช้ได้ (ระบบดูรูปแบบจากโฟลเดอร์เอง) หรือแปลงเป็นรูปแบบ 1.0 ด้วย `uv run atlas corpus convert <โฟลเดอร์ .md> --out <โฟลเดอร์ใหม่>` (รหัสบทความเดิม)
ตัวอย่างไฟล์ (บทความสมมติ) อยู่ใน `docs/corpus/example/` — คู่มือเต็มอยู่ใน `docs/corpus/README.md`

## เว็บมีอะไรบ้าง

เว็บเป็น **dashboard**: เมนูซ้ายสีขาว (บนมือถือกดปุ่มเมนูเพื่อเปิด) ทุกหน้ามีแถบหัวสีขาวบอกชื่อหน้า คำอธิบายสั้น 1 บรรทัด และรอบข้อมูล ส่วนเนื้อหาเป็นการ์ดสีขาวบนพื้นเทาอมฟ้า

| เมนู | หน้า |
|---|---|
| **แดชบอร์ด** | ภาพรวม (เป็นสรุปผู้บริหารด้วย กด "พิมพ์ / บันทึก PDF" ได้กระดาษ A4 2 หน้า) · หัวข้อวิจัย · สถาบันและจังหวัด · วารสาร · เป้าหมายชาติและโลก |
| **แผนที่** | แผนที่หัวข้อ · แผนที่บทความทุกเรื่อง |
| **คำอธิบาย** | อ่านตัวเลขอย่างไร |

จาก dashboard กด "ดูทั้งหมด" หรือกดชื่อในรายการ เพื่อไปหน้ารายละเอียดของหัวข้อ วารสาร สถาบัน หรือจังหวัด

- **2 ภาษา** ไทยและอังกฤษ ทุกหน้า
- **สั้น เลื่อนน้อย** — การ์ดแต่ละใบมีแค่ชื่อ กราฟหรือรายการ และ "ดูทั้งหมด" คำอธิบายวิธีคิดอยู่หลังปุ่ม ⓘ ข้างชื่อการ์ด และรวมไว้ครบที่หน้า "อ่านตัวเลขอย่างไร"
- **ภาษาง่าย** — ประโยคสั้น ขึ้นด้วยตัวอย่าง ใช้ปีแทนศัพท์สถิติ
- แชร์ลิงก์พร้อมตัวกรองที่เลือกไว้ได้
- **หน้าไม่มีวันขาว** — ข้อมูลโหลดไม่ได้หรือบางส่วนพัง หน้าเว็บบอกเหตุผล ข้อมูลทดสอบมีป้าย "ข้อมูลตัวอย่าง" ที่แถบหัวทุกหน้า
- กราฟฝังในเว็บอื่นได้ (`#/embed/topic/<รหัส>`, `#/embed/emerging`) ฟีด Atom ต่อรอบและต่อหัวข้อ (เมื่อตั้ง `publish.site_url`) และข้อมูลสำหรับ Google/การแชร์ลิงก์ (Open Graph, schema.org Dataset, sitemap)
- ตั้งแต่ 2026-10-24 ไม่มีหน้าค้นหาบทความ เปรียบเทียบหัวข้อ วางบทคัดย่อ ข้อมูลเปิด และไม่มีปุ่มดาวน์โหลด CSV แล้ว ลิงก์เก่าพาไปหน้าที่รับเนื้อหาแทน (เหตุผลอยู่ใน [`docs/ROADMAP.md`](docs/ROADMAP.md))
- วิธีอ้างอิง Atlas: [`CITATION.cff`](CITATION.cff) — ข้อมูลเผยแพร่ภายใต้ CC BY 4.0

เว็บสาธิตบน GitHub Pages ใช้ **ข้อมูลสังเคราะห์** (มีป้าย "ข้อมูลตัวอย่าง" และไม่ให้ search engine เก็บ) ขั้นตอนขึ้นข้อมูลจริง: `docs/OPERATIONS.md` §1.5

## ข้อมูลส่วนบุคคล (PDPA)

- เว็บและไฟล์ที่เผยแพร่ **ไม่มีชื่อผู้แต่ง ไม่มีบทคัดย่อ และไม่มีข้อมูลรายบุคคล** — มีแต่ตัวเลขรวมระดับหัวข้อ วารสาร สถาบัน และจังหวัด
- ชื่อผู้แต่งในคลังถูกอ่านเพื่อหาสังกัดเท่านั้น
- `atlas validate` และ `atlas publish` มีด่านตรวจความเป็นส่วนตัว: ถ้าพบอีเมล รหัส ORCID หรือชื่อผู้แต่งปนอยู่ในชื่อหน่วยงาน รอบนั้นจะไม่ถูกเผยแพร่
- ข้อมูลจริง (คลังบทความ รอบข้อมูลจริง ทะเบียนวารสาร/สถาบัน) **ไม่เข้า git** — repo มีแต่ตัวอย่าง 11 ไฟล์ใน `pipeline/tests/fixtures/thaijo_md/`, คลังสมมติใน `docs/corpus/example/` และรอบข้อมูลสังเคราะห์ใน `web/fixtures/`

## สถานะของหัวข้อ (นิยาม v3 ย่อ)

ระบบเทียบ **3 ปีล่าสุดที่ข้อมูลครบ** กับ **5 ปีก่อนหน้านั้น** (ไม่นับปีที่กำลังดำเนินอยู่ และตัดปีล่าสุดที่ข้อมูลยังเข้าไม่ครบออกให้เอง) แล้วให้แต่ละหัวข้อ 1 สถานะ โดยดูช่วงที่การเติบโตน่าจะอยู่ ไม่ใช่ตัวเลขตัวเดียว

| สถานะ | ความหมาย (ค่าเริ่มต้น) |
|---|---|
| ◯ **ข้อมูลน้อย** (LOW_DATA) | บทความใน 3 ปีล่าสุดน้อยกว่า 30 เรื่อง หรือคำนวณการเติบโตไม่ได้ — ไม่ฟันธง |
| ▲ **กำลังเกิดใหม่** (EMERGING) | หัวข้อเล็ก ส่วนแบ่งโตอย่างน้อย 10% ต่อปีแม้คิดแบบระวังที่สุด ส่วนแบ่งเพิ่มเป็น 1.8 เท่าขึ้นไป และมาจากหลายวารสารหลายสถาบัน |
| ◆ **จับตา** (WATCH) | โตเร็วเหมือนกำลังเกิดใหม่ แต่ยังมาจากไม่กี่วารสารหรือไม่กี่สถาบัน |
| ● **กำลังมาแรง** (HOT) | หัวข้อใหญ่ที่ส่วนแบ่งยังโตต่อ |
| ▼ **ลดลง** (DECLINING) | ส่วนแบ่งลดลงชัดเจน และเหลือไม่เกิน 0.8 เท่าของเดิม |
| ■ **คงที่** (STABLE) | อื่น ๆ |

ตรวจตามลำดับในตาราง ข้อแรกที่เข้าคือคำตอบ · คะแนน 0–100 ใช้จัดอันดับภายในรอบเท่านั้น เทียบข้ามรอบไม่ได้ · สูตรเต็มและเหตุผล: `docs/EMERGING_SPEC.md`

## การพยากรณ์

ระบบพยากรณ์จำนวนบทความของแต่ละหัวข้อล่วงหน้า 2 ปี (ส่วนแบ่งของหัวข้อ × ยอดรวมของคลัง) โดยลองหลายวิธีกับข้อมูลย้อนหลังแล้วเลือกวิธีที่แม่นที่สุดต่อหัวข้อ — **แสดงเส้นพยากรณ์เฉพาะหัวข้อที่แม่นกว่าการเดาว่า "เท่าปีล่าสุด"** หัวข้ออื่นเว็บเขียนว่า "แนวโน้มไม่แน่นอน"

## โครงสร้าง repo

```
pipeline/   ระบบวิเคราะห์ (Python) + config.example.yaml           → pipeline/README.md
web/        เว็บ (React) + ข้อมูลสังเคราะห์ใน fixtures/              → web/README.md
docs/       คู่มือและสเปก (ดูตาราง "อ่านอะไรต่อ")
prompts/    คำสั่งที่ส่งให้ LLM (ไฟล์เดียวต่องาน)
scripts/    quarterly_run.sh · quarterly_run.cmd (ดับเบิลคลิกบน Windows) · import_atlas.sh · package_release.sh (GitHub Pages)
runs/ deploy/   สร้างตอนรันรอบ (ไม่เข้า git)
```
