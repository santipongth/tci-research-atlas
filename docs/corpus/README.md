# คู่มือเตรียมคลังบทความสำหรับ TCI Research Atlas (รูปแบบ 1.0)

คู่มือนี้สำหรับทีมที่เตรียมข้อมูลบทความจาก TCI และ ThaiJO ให้ระบบ Atlas นำไปวิเคราะห์
ถ้าเตรียมตามนี้ ระบบอ่านได้ทันทีโดยไม่ต้องเดา และตัวเลขบนเว็บจะถูกต้อง

- **ตัวอย่างไฟล์จริง:** [`example/articles/part-0001.jsonl`](example/articles/part-0001.jsonl) และ [`example/journals.csv`](example/journals.csv) เป็นข้อมูลสมมติ 7 บทความ
- **ไฟล์ตรวจรูปแบบ:** [`corpus.schema.json`](corpus.schema.json) (มาตรฐาน JSON Schema) และสคริปต์ตรวจแบบเบา [`validate_jsonl.py`](validate_jsonl.py)

---

## 1. ส่งอะไรมาบ้าง

```
corpus/
├── articles/
│   ├── part-0001.jsonl.gz      ← ไฟล์ละไม่เกิน 50,000 บทความ (บีบอัด .gz หรือไม่ก็ได้)
│   ├── part-0002.jsonl.gz
│   └── …
├── journals.csv                ← 1 แถวต่อวารสาร
└── README.txt                  ← (ไม่บังคับ) วันที่ดึงข้อมูล แหล่งที่มา ผู้เตรียม
```

- **ไฟล์ `.jsonl` (JSON Lines):** 1 บรรทัด = 1 บทความ เป็น JSON ที่สมบูรณ์ในตัวเอง ห้ามขึ้นบรรทัดใหม่กลางบทความ
- **การเข้ารหัส:** UTF-8 ไม่มี BOM
- **ลำดับบทความ:** ไม่สำคัญ และจะแบ่งไฟล์อย่างไรก็ได้
- **ไฟล์ที่ชื่อขึ้นต้นด้วย `_`:** ระบบข้าม ใช้เก็บไฟล์ทดลองได้

ทำไมไม่ใช้ Markdown หรือ BibTeX:
- **Markdown:** เครื่องต้องเดาว่าตรงไหนคือบทคัดย่อไทยหรืออังกฤษ ตรงไหนคือชื่อคนหรือสังกัด ถ้าเดาผิดก็ไม่มีใครรู้
- **BibTeX:** ไม่มีช่องสำหรับชื่อเรื่องและบทคัดย่อสองภาษา สังกัดรายคน และรายการอ้างอิง
- **JSONL:** ทุกช่องมีชื่อชัดเจน และตรวจได้ทีละบรรทัด

## 3. ช่องข้อมูลทั้งหมด

ระดับความสำคัญ:
- 🔴 **ต้องมี:** ขาดแล้วระบบไม่รับบรรทัดนั้น
- 🟠 **ต้องมีถ้าต้นฉบับมี:** ระบบรับได้ แต่ผลวิเคราะห์จะด้อยลงมาก
- 🟡 **ควรมี:** ทำให้หน้าเว็บครบ
- 🟢 **มีก็ดี:** ใช้ต่อยอด

ช่องที่ไม่มีข้อมูล ให้ใส่ `null` หรือไม่ใส่ช่องนั้นเลย **ห้ามใส่** `""`, `"-"` หรือ `"N/A"`

### 3.1 ตัวบทความ

| ช่อง | ระดับ | ชนิด | ตัวอย่าง | กติกา |
|---|---|---|---|---|
| `schema` | 🔴 | ข้อความ | `"tci-atlas-corpus/1.0"` | ค่านี้เท่านั้น |
| `journal_key` | 🔴 | ข้อความ | `"so02:SampleJournal"` | รหัสวารสาร ต้องตรงกับแถวใน `journals.csv` (ดู §5) |
| `title` | 🔴 | `{th, en}` | | ต้องมีอย่างน้อยหนึ่งภาษา |
| `year` / `published` | 🟠 | ตัวเลข / วันที่ | `2024` / `"2024-06-28"` | ใส่อย่างน้อยหนึ่งช่อง ปีเป็น **ค.ศ. เท่านั้น** วันที่ใช้รูป `YYYY-MM-DD` ถ้าใส่ทั้งสองช่อง ปีต้องตรงกัน ถ้ารู้แค่เดือน ให้ใส่แค่ `year` |
| `abstract` | 🟠 | `{th, en}` | | เป็นตัวหลักที่ใช้จัดหัวข้อวิจัย มีครบสองภาษายิ่งดี |
| `id` | 🟡 | ข้อความ | `"tci:A-000777"` | ไม่ใส่ก็ได้ ระบบสร้างให้ (ดู §4) ถ้าใส่ **ห้ามเปลี่ยนข้ามรอบ** |
| `url` | 🟡 | URL | `"https://so02.tci-thaijo.org/…/article/view/245871"` | หน้าบทความ เริ่มด้วย `http(s)://` |
| `doi` | 🟡 | ข้อความ | `"10.5555/sjbe.2024.12"` | ไม่มี `https://doi.org/` นำหน้า |
| `keywords` | 🟡 | `{th: [...], en: [...]}` | | คำสำคัญของผู้แต่ง 1 คำต่อ 1 ช่องใน list ไม่ใช่ `"ก, ข, ค"` |
| `authors` | 🟡 | list | | ดู §3.2 |
| `article_type` | 🟡 | ค่าที่กำหนด | `"research-article"` | ดู §3.4 ระบบตัดบทบรรณาธิการ คำแก้ และบทวิจารณ์หนังสือออก |
| `references` | 🟡 | list | | ดู §3.3 ใช้นับการอ้างอิงภายในฐาน TCI |
| `issn`, `eissn` | 🟡 | ข้อความ | `"1905-9566"` | รูป `NNNN-NNNN` (ตัวท้ายเป็น X ได้) |
| `volume`, `issue` | 🟡 | ข้อความ | `"19"`, `"2"` | ใช้เติมปีให้บทความที่ไม่มีวันที่ จากบทความอื่นในฉบับเดียวกัน |
| `issue_url` | 🟢 | URL | | หน้าฉบับ (ถ้ามี) |
| `pages` | 🟢 | `{first, last}` | `{"first": "45", "last": "62"}` | |
| `language` | 🟢 | รหัส 2 ตัว | `"th"` | ภาษาของเนื้อหาบทความ ตาม ISO 639-1 |
| `source` | 🟢 | `thaijo` / `tci` / `other` | | ได้มาจากระบบไหน |
| `journal_title` | 🟢 | `{th, en}` | | ถ้า `journals.csv` มีชื่อวารสารแล้ว ไม่ต้องใส่ |
| `funding` | 🟢 | list ของ `{funder, grant_id}` | | แหล่งทุน ใช้ตอบว่าทุนไปลงหัวข้อไหน |

### 3.2 ผู้แต่ง (`authors`)

| ช่อง | ระดับ | กติกา |
|---|---|---|
| `name` `{th, en}` | 🔴 (ต่อคน) | ใช้แยกคนภายในระบบเท่านั้น **ไม่เคยแสดงบนเว็บ** (PDPA) |

| `orcid` | 🟢 | `0000-0000-0000-0000` |
| `corresponding` | 🟢 | `true` / `false` |
| `role` | 🟢 | `lecturer` · `researcher` · `student-master` · `student-doctoral` · `student` · `other` |

### 3.3 รายการอ้างอิง (`references`)

| ช่อง | กติกา |
|---|---|
| `text` | **1 รายการอ้างอิงเต็ม = 1 ช่อง** ต่อบรรทัดที่ถูกตัดให้เรียบร้อยก่อน |
| `year` | ปี ค.ศ. ของงานที่อ้าง ถ้าไม่ใส่ ระบบอ่านจากวงเล็บปีในข้อความ |

| `translated` | `true` ถ้ารายการนี้เป็นฉบับแปลภาษาอังกฤษของรายการภาษาไทยที่มีอยู่แล้ว (ส่วน "Translated Thai References") ระบบจะไม่นับซ้ำ |

ระบบไม่เผยแพร่ข้อความรายการอ้างอิง ใช้เพียงนับว่าบทความใดในฐาน TCI ถูกอ้างอิง

## 4. รหัสบทความ (`id`) — ห้ามเปลี่ยนข้ามรอบ

ระบบใช้รหัสนี้ตามรอยหัวข้อวิจัยข้ามไตรมาส และบอกได้ว่ารอบนี้มีอะไรเปลี่ยน ถ้ารหัสเปลี่ยน ระบบจะคิดว่าเป็นบทความใหม่

ถ้าไม่ใส่ `id` ระบบสร้างให้ตามลำดับนี้:
1. **มี `url` ของ ThaiJO:** ได้ `so02:SampleJournal:245871` ซึ่งตรงกับรหัสที่ใช้อยู่แล้ว ประวัติหัวข้อจึงต่อเนื่อง
2. **ไม่มี url แต่มี `doi`:** ได้ `doi:10.5555/tmj.2023.0451`
3. **ไม่มีทั้งสองอย่าง:** ระบบสร้างจาก `journal_key` + ชื่อเรื่อง + ปี เช่น `tci:3f9a…` ดังนั้น **อย่าแก้ชื่อเรื่องหรือปีของบทความเดิมในรอบถัดไป** ถ้าจำเป็นต้องแก้ ให้ใส่ `id` เองตั้งแต่รอบแรก

บทความเดียวกันที่อยู่ทั้งใน TCI และ ThaiJO ส่งมาทั้งสองแถวได้ ถ้ามี DOI เดียวกันหรือชื่อเรื่องตรงกัน ระบบตัดซ้ำและเก็บแถวที่ข้อมูลครบกว่า

## 5. รหัสวารสาร (`journal_key`) และ `journals.csv`

- **วารสารบน ThaiJO:** ใช้ `<server>:<ชื่อวารสารใน URL>` เช่น URL `https://so02.tci-thaijo.org/index.php/SampleJournal/…` ได้ `so02:SampleJournal`
- **วารสารที่ไม่ได้อยู่บน ThaiJO:** ตั้งรหัสเอง ขึ้นต้นด้วย `tci:` แล้วตามด้วยตัวอักษรอังกฤษ ตัวเลข หรือ `-` เช่น `tci:sample-medical-journal`
- **ข้อห้าม:** ห้ามมีช่องว่างหรืออักษรไทย และห้ามเปลี่ยนรหัสข้ามรอบ

`journals.csv` มี 1 แถวต่อวารสาร (UTF-8) คอลัมน์ดังนี้:

| คอลัมน์ | ระดับ | ตัวอย่าง |
|---|---|---|
| `journal_key` | 🔴 | `so02:SampleJournal` |
| `name_th`, `name_en` | 🟡 | ชื่อเต็มของวารสาร |
| `issn`, `eissn` | 🟡 | `1905-9566` |
| `tci_tier` | 🟡 | `1`, `2` หรือ `3` (กลุ่มวารสาร TCI) |
| `tci_field` | 🟡 | สาขาของ TCI |
| `publisher_org` | 🟢 | สถาบันเจ้าของวารสาร |
| `url` | 🟢 | หน้าแรกของวารสาร |

## 6. กติกาความสะอาดของข้อความ

1. **การเข้ารหัส:** UTF-8 และ Unicode แบบ NFC
   - อักษรไทยต้องไม่เพี้ยนจาก PDF เช่น `ํา` ต้องเป็น `ำ` และต้องไม่มีอักษรแปลกในช่วง U+F700–F71A (ระบบซ่อมให้ได้บางส่วน)
2. **ไม่มีแท็ก HTML:** เช่น `<p>`, `<br>` และไม่มี `&nbsp;`
3. **ไม่ตัดบรรทัดกลางประโยค:** บทคัดย่อ 1 ภาษาเป็นข้อความต่อเนื่องก้อนเดียว
4. **แยกภาษาให้ถูกช่อง:** บทคัดย่อไทยอยู่ใน `abstract.th` อังกฤษอยู่ใน `abstract.en` ห้ามรวมกันในช่องเดียว
5. **ไม่มีคำนำหน้าช่อง:** เช่นไม่มีคำว่า "บทคัดย่อ" หรือ "Abstract" นำหน้า และไม่มี "คำสำคัญ:" ใน keywords
6. **ปีเป็น ค.ศ. เสมอ:** ถ้าต้นฉบับเป็น พ.ศ. ให้ลบ 543 ระบบไม่รับปีที่เกิน 2400 เพราะเป็นปี พ.ศ.
7. **ไม่ใส่เนื้อหาบทความฉบับเต็ม:** ระบบไม่ใช้ ทำให้ไฟล์ใหญ่ และมีประเด็นลิขสิทธิ์
8. **ไม่ใส่คำนำหน้าวิชาการในชื่อคน:** ตำแหน่งอย่าง "ผศ.ดร." ให้ใส่ใน `role` แทน
9. **คำสำคัญ 1 คำต่อ 1 ช่อง:** ตัดช่องว่างหัวท้าย และไม่ใส่คำซ้ำ

## 7. ข้อมูลส่วนบุคคล (PDPA)

- ไฟล์คลังมีชื่อผู้แต่ง จึงเป็นข้อมูลส่วนบุคคล ส่งผ่านช่องทางภายในองค์กรเท่านั้น **ห้ามอัปโหลดขึ้นที่สาธารณะ ห้าม commit ลง GitHub และห้ามแนบอีเมลนอกองค์กร**
- เว็บ Atlas เผยแพร่เฉพาะตัวเลขรวม เช่น จำนวนบทความ สัดส่วน และชื่อสถาบัน ไม่เคยแสดงชื่อบุคคล บทคัดย่อ หรือข้อความรายการอ้างอิง

## 8. ตรวจไฟล์เองก่อนส่ง

**วิธีที่ 1: ใช้ Atlas** (ผลละเอียดที่สุด ใช้ได้บนเครื่องที่ติดตั้ง pipeline)

```bash
cd pipeline
uv run atlas profile /path/to/corpus --md profile.md
```

- รายงานบอกจำนวนบรรทัดที่ผิด พร้อมตำแหน่ง `ไฟล์:บรรทัด` และเหตุผล
  - เช่น `articles/part-0003.jsonl:1288: ValidationError: year: year 2567 looks like a Buddhist Era year…`
- บอกว่าแต่ละช่องกรอกครบกี่ %
- บอกว่ารหัสบทความมาจาก url, doi หรือระบบสร้างให้ กี่เรื่อง
- คำสั่งจบด้วย exit 1 ถ้าบรรทัดที่ผิดเกิน 1%

**วิธีที่ 2: ใช้สคริปต์ตรวจแบบเบา** (ไม่ต้องติดตั้ง Atlas ใช้แค่ Python 3.9 ขึ้นไป)

```bash
pip install jsonschema
python docs/corpus/validate_jsonl.py /path/to/corpus        # ตรวจทุกไฟล์ใน articles/
```

ผลจะแสดงทีละบรรทัดที่ผิด เช่น `part-0001.jsonl:1: (line): Additional properties are not allowed ('abstarct' was unexpected)` ซึ่งหมายถึงชื่อช่องสะกดผิด

สคริปต์นี้ตรวจรูปแบบของแต่ละช่องด้วย [`corpus.schema.json`](corpus.schema.json) แต่ไม่ตรวจกติกาที่ข้ามช่อง เช่น "ปีตรงกับวันที่" และ "จังหวัดต้องเป็น 1 ใน 77" ก่อนส่งงานจริงให้ใช้วิธีที่ 1 ยืนยันอีกครั้ง

## 9. Checklist ก่อนส่ง

- [ ] ทุกบรรทัดมี `"schema": "tci-atlas-corpus/1.0"`, `journal_key` และ `title`
- [ ] ปีเป็น ค.ศ. วันที่เป็น `YYYY-MM-DD`
- [ ] บทคัดย่อแยกไทยและอังกฤษ ไม่มีคำนำหน้า ไม่มี HTML
- [ ] สังกัดแยกรายการต่อคน ไม่รวมเป็นข้อความเดียว
- [ ] รายการอ้างอิง 1 รายการต่อ 1 ช่อง
- [ ] ทุก `journal_key` มีแถวใน `journals.csv`
- [ ] รหัสบทความและรหัสวารสารเหมือนรอบก่อน (ถ้าเคยส่งแล้ว)
- [ ] `atlas profile` ไม่มีบรรทัดที่ผิด หรือผิดน้อยกว่า 1% และรู้สาเหตุ
- [ ] ส่งผ่านช่องทางภายในองค์กรเท่านั้น

## 10. คำถามที่พบบ่อย

- **บทความไม่มีบทคัดย่อ:** ส่งได้ ระบบใช้ชื่อเรื่องและคำสำคัญแทน แต่จัดหัวข้อได้แม่นน้อยกว่า
- **ไม่รู้วันที่ รู้แค่เล่มและฉบับ:** ใส่ `volume` + `issue` ระบบเติมปีจากบทความอื่นในฉบับเดียวกัน
- **ผู้แต่งมี 2 สังกัด:** ใส่ 2 รายการใน `affiliations` ระบบนับให้ทั้งสองสถาบัน
- **มีข้อมูลที่ไม่อยู่ในตาราง:** ใส่ใน `extra` เช่น `"extra": {"tci_article_no": "A-000777"}`
- **ตารางนี้มีช่องที่ทีมไม่มีข้อมูล:** ไม่ใส่ได้เลย ยกเว้นช่อง 🔴
- **ส่งคลังทั้งหมดใหม่ทุกไตรมาส หรือเฉพาะบทความใหม่:** ส่ง **ทั้งหมด** ทุกรอบ ระบบรู้เองว่าเรื่องไหนเคยประมวลผลแล้ว และจ่ายค่าประมวลผลเฉพาะเรื่องใหม่หรือเรื่องที่ข้อความเปลี่ยน
- **มีไฟล์ Markdown แบบ ThaiJO เดิมอยู่แล้ว:** แปลงเป็นรูปแบบนี้ได้ด้วย `uv run atlas corpus convert <โฟลเดอร์ .md> --out <โฟลเดอร์ใหม่>` แล้วเติมช่องที่ขาด เช่น `article_type`, ISSN, ORCID และจังหวัด
