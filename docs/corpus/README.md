# คู่มือเตรียมคลังบทความสำหรับ TCI Research Atlas (รูปแบบ 1.0)

คู่มือนี้สำหรับทีมที่เตรียมข้อมูลบทความจาก TCI และ ThaiJO ให้ระบบ Atlas นำไปวิเคราะห์
ถ้าเตรียมตามนี้ ระบบอ่านได้ทันทีโดยไม่ต้องเดา และตัวเลขบนเว็บจะถูกต้อง

- **ตัวอย่างไฟล์จริง:** [`example/articles/part-0001.jsonl`](example/articles/part-0001.jsonl) เป็นบทความสมมติ 7 เรื่อง พร้อม [`example/journals.csv`](example/journals.csv) และ [`example/institutions_aliases.csv`](example/institutions_aliases.csv)
- **อ่านตามลำดับนี้:**
  1. หัวข้อ 13 ขั้นตอนทำงาน
  2. หัวข้อ 1–7 รูปแบบไฟล์บทความ
  3. หัวข้อ 11 ไฟล์ประกอบและหลักการตัดสินใจ
  4. หัวข้อ 12 ติดตั้งและตรวจไฟล์เอง
- **ไฟล์ตรวจรูปแบบ:** [`corpus.schema.json`](corpus.schema.json) (มาตรฐาน JSON Schema) และสคริปต์ตรวจแบบเบา [`validate_jsonl.py`](validate_jsonl.py)

## 1. ส่งอะไรมาบ้าง

```
corpus/
├── articles/
│   ├── part-0001.jsonl.gz      ← ไฟล์ละไม่เกิน 50,000 บทความ (บีบอัด .gz หรือไม่ก็ได้)
│   ├── part-0002.jsonl.gz
│   └── …
├── journals.csv                ← 1 แถวต่อวารสาร (บังคับ — หัวข้อ 11.1)
├── institutions_aliases.csv    ← ชื่อสถาบันที่เขียนต่างกัน → สถาบันเดียว (แนะนำมาก — หัวข้อ 11.2)
├── province_population.csv     ← ประชากร 77 จังหวัด (แนะนำ — หัวข้อ 11.3)
├── ror.zip                     ← ฐาน ROR (ไม่บังคับ — หัวข้อ 11.4)
└── README.txt                  ← บันทึกการตัดสินใจและที่มาข้อมูล (บังคับ — หัวข้อ 11.5)
```

- **ไฟล์ `.jsonl` (JSON Lines):** 1 บรรทัด = 1 บทความ เป็น JSON ที่สมบูรณ์ในตัวเอง ห้ามขึ้นบรรทัดใหม่กลางบทความ
- **การเข้ารหัส:** UTF-8 ไม่มี BOM
- **ลำดับบทความ:** ไม่สำคัญ และจะแบ่งไฟล์อย่างไรก็ได้
- **ไฟล์ที่ชื่อขึ้นต้นด้วย `_`:** ระบบข้าม ใช้เก็บไฟล์ทดลองได้

ทำไมไม่ใช้ Markdown หรือ BibTeX:
- **Markdown:** เครื่องต้องเดาว่าตรงไหนคือบทคัดย่อไทยหรืออังกฤษ ตรงไหนคือชื่อคนหรือสังกัด ถ้าเดาผิดก็ไม่มีใครรู้
- **BibTeX:** ไม่มีช่องสำหรับชื่อเรื่องและบทคัดย่อสองภาษา สังกัดรายคน และรายการอ้างอิง
- **JSONL:** ทุกช่องมีชื่อชัดเจน และตรวจได้ทีละบรรทัด

## 3. ช่องข้อมูลทั้งหมด

ระดับความสำคัญ:
- 🔴 **ต้องมี:** ขาดแล้วระบบไม่รับบรรทัดนั้น
- 🟠 **ต้องมีถ้าต้นฉบับมี:** ระบบรับได้ แต่ผลวิเคราะห์จะด้อยลงมาก
- 🟡 **ควรมี:** ทำให้หน้าเว็บครบ
- 🟢 **มีก็ดี:** ใช้ต่อยอด

ช่องที่ไม่มีข้อมูล ให้ใส่ `null` หรือไม่ใส่ช่องนั้นเลย **ห้ามใส่** `""`, `"-"` หรือ `"N/A"`

| ช่อง | ระดับ | ชนิด | ตัวอย่าง | กติกา |
|---|---|---|---|---|
| `schema` | 🔴 | ข้อความ | `"tci-atlas-corpus/1.0"` | ค่านี้เท่านั้น |
| `journal_key` | 🔴 | ข้อความ | `"so02:SampleJournal"` | รหัสวารสาร ต้องตรงกับแถวใน `journals.csv` (ดู §5) |
| `title` | 🔴 | `{th, en}` | | ต้องมีอย่างน้อยหนึ่งภาษา |
| `year` / `published` | 🟠 | ตัวเลข / วันที่ | `2024` / `"2024-06-28"` | ใส่อย่างน้อยหนึ่งช่อง ปีเป็น **ค.ศ. เท่านั้น** วันที่ใช้รูป `YYYY-MM-DD` ถ้าใส่ทั้งสองช่อง ปีต้องตรงกัน ถ้ารู้แค่เดือน ให้ใส่แค่ `year` |
| `abstract` | 🟠 | `{th, en}` | | เป็นตัวหลักที่ใช้จัดหัวข้อวิจัย มีครบสองภาษายิ่งดี |

| `url` | 🟡 | URL | `"https://so02.tci-thaijo.org/…/article/view/245871"` | หน้าบทความ เริ่มด้วย `http(s)://` |

| `issn`, `eissn` | 🟡 | ข้อความ | `"1905-9566"` | รูป `NNNN-NNNN` (ตัวท้ายเป็น X ได้) |
| `volume`, `issue` | 🟡 | ข้อความ | `"19"`, `"2"` | ใช้เติมปีให้บทความที่ไม่มีวันที่ จากบทความอื่นในฉบับเดียวกัน |

| ช่อง | กติกา |

## 4. รหัสบทความ (`id`) — ห้ามเปลี่ยนข้ามรอบ

ระบบใช้รหัสนี้ตามรอยหัวข้อวิจัยข้ามไตรมาส และบอกได้ว่ารอบนี้มีอะไรเปลี่ยน ถ้ารหัสเปลี่ยน ระบบจะคิดว่าเป็นบทความใหม่

ถ้าไม่ใส่ `id` ระบบสร้างให้ตามลำดับนี้:
1. **มี `url` ของ ThaiJO:** ได้ `so02:SampleJournal:245871` ซึ่งตรงกับรหัสที่ใช้อยู่แล้ว ประวัติหัวข้อจึงต่อเนื่อง
2. **ไม่มี url แต่มี `doi`:** ได้ `doi:10.5555/tmj.2023.0451`
3. **ไม่มีทั้งสองอย่าง:** ระบบสร้างจาก `journal_key` + ชื่อเรื่อง + ปี เช่น `tci:3f9a…` ดังนั้น **อย่าแก้ชื่อเรื่องหรือปีของบทความเดิมในรอบถัดไป** ถ้าจำเป็นต้องแก้ ให้ใส่ `id` เองตั้งแต่รอบแรก

บทความเดียวกันที่อยู่ทั้งใน TCI และ ThaiJO ส่งมาทั้งสองแถวได้ ถ้ามี DOI เดียวกันหรือชื่อเรื่องตรงกัน ระบบตัดซ้ำและเก็บแถวที่ข้อมูลครบกว่า

## 5. รหัสวารสาร (`journal_key`) และ `journals.csv`

- **วารสารบน ThaiJO:** ใช้ `<server>:<ชื่อวารสารใน URL>` เช่น URL `https://so02.tci-thaijo.org/index.php/SampleJournal/…` ได้ `so02:SampleJournal`
- **วารสารที่ไม่ได้อยู่บน ThaiJO:** `tci:` + ISSN ฉบับพิมพ์ (ไม่มีจึงใช้ e-ISSN) เช่น `tci:0125-2526` ถ้าไม่มี ISSN เลย ใช้ `tci:` + ชื่อย่อภาษาอังกฤษตัวเล็ก เช่น `tci:sample-medical-journal` (ดูหลักการเต็มในหัวข้อ 11.1)
- **ข้อห้าม:** ห้ามมีช่องว่างหรืออักษรไทย และห้ามเปลี่ยนรหัสข้ามรอบ

`journals.csv` มี 1 แถวต่อวารสาร (UTF-8) คอลัมน์ดังนี้:

| คอลัมน์ | ระดับ | ตัวอย่าง |
|---|---|---|
| `journal_key` | 🔴 | `so02:SampleJournal` |
| `name_th`, `name_en` | 🟡 | ชื่อเต็มของวารสาร |
| `issn`, `eissn` | 🟡 | `1905-9566` |
| `tci_tier` | 🟡 | `1`, `2` หรือ `3` (กลุ่มวารสาร TCI) |
| `tci_field` | 🟡 | สาขาของ TCI |
| `publisher_org` | 🟢 | สถาบันเจ้าของวารสาร |
| `url` | 🟢 | หน้าแรกของวารสาร |

## 6. กติกาความสะอาดของข้อความ

1. **การเข้ารหัส:** UTF-8 และ Unicode แบบ NFC
   - อักษรไทยต้องไม่เพี้ยนจาก PDF เช่น `ํา` ต้องเป็น `ำ` และต้องไม่มีอักษรแปลกในช่วง U+F700–F71A (ระบบซ่อมให้ได้บางส่วน)
2. **ไม่มีแท็ก HTML:** เช่น `<p>`, `<br>` และไม่มี `&nbsp;`
3. **ไม่ตัดบรรทัดกลางประโยค:** บทคัดย่อ 1 ภาษาเป็นข้อความต่อเนื่องก้อนเดียว
4. **แยกภาษาให้ถูกช่อง:** บทคัดย่อไทยอยู่ใน `abstract.th` อังกฤษอยู่ใน `abstract.en` ห้ามรวมกันในช่องเดียว
5. **ไม่มีคำนำหน้าช่อง:** เช่นไม่มีคำว่า "บทคัดย่อ" หรือ "Abstract" นำหน้า และไม่มี "คำสำคัญ:" ใน keywords
6. **ปีเป็น ค.ศ. เสมอ:** ถ้าต้นฉบับเป็น พ.ศ. ให้ลบ 543 ระบบไม่รับปีที่เกิน 2400 เพราะเป็นปี พ.ศ.
7. **ไม่ใส่เนื้อหาบทความฉบับเต็ม:** ระบบไม่ใช้ ทำให้ไฟล์ใหญ่ และมีประเด็นลิขสิทธิ์
8. **ไม่ใส่คำนำหน้าวิชาการในชื่อคน:** ตำแหน่งอย่าง "ผศ.ดร." ให้ใส่ใน `role` แทน
9. **คำสำคัญ 1 คำต่อ 1 ช่อง:** ตัดช่องว่างหัวท้าย และไม่ใส่คำซ้ำ

### 11.1 `journals.csv`: รหัส กลุ่ม และสาขาของวารสาร

**รหัสวารสาร (`journal_key`):** ตั้งครั้งเดียว ใช้ตลอดไป

| กรณี | รหัส | ตัวอย่าง |
|---|---|---|
| วารสารอยู่บน ThaiJO | `<server>:<ชื่อวารสารใน URL>` | `https://so02.tci-thaijo.org/index.php/BECJournal/…` → `so02:BECJournal` |
| ไม่อยู่บน ThaiJO และมี ISSN | `tci:` + ISSN ฉบับพิมพ์ (ไม่มีจึงใช้ e-ISSN) | `tci:0125-2526` |
| ไม่อยู่บน ThaiJO และไม่มี ISSN | `tci:` + ชื่อย่อภาษาอังกฤษตัวเล็ก คั่นด้วย `-` | `tci:sample-medical-journal` |

- **ห้ามเปลี่ยนรหัสที่เคยใช้แล้ว** แม้วารสารจะเปลี่ยน ISSN เปลี่ยนชื่อ หรือย้ายเข้า ThaiJO ภายหลัง ให้คงรหัสเดิม แล้วแก้ข้อมูลในคอลัมน์อื่นแทน
- `journals.csv` ของรอบใหม่ = ไฟล์ของรอบก่อน + แถวของวารสารใหม่ **ห้ามลบแถวเก่า** แม้วารสารนั้นจะไม่มีบทความในรอบนี้แล้ว
- ทุกบทความใน `articles/` ต้องใช้ `journal_key` ที่มีแถวอยู่ใน `journals.csv` (`atlas profile` ตรวจให้)

**กลุ่ม TCI (`tci_tier`):**
- **ที่มา:** รายชื่อวารสารที่ผ่านการรับรองคุณภาพของ TCI ฉบับล่าสุด ที่เว็บไซต์ tci-thailand.org
- **ค่าที่ใส่:** `1`, `2` หรือ `3` ตามรายชื่อนั้น
- **วารสารที่ไม่อยู่ในรายชื่อ** (เช่น ถูกถอดออก): เว้นว่าง ห้ามเดา
- **บันทึกใน `README.txt`:** ชื่อไฟล์หรือ URL ของรายชื่อที่ใช้ และวันที่ดาวน์โหลด

**สาขา (`tci_field`):**
- คัดลอกชื่อกลุ่มสาขาจากรายชื่อเดียวกัน **ตามตัวอักษรเป๊ะ** ให้ทุกวารสารในกลุ่มเดียวกันสะกดเหมือนกันทุกตัวอักษร (เว็บใช้ค่านี้จัดกลุ่ม)
- ถ้ารายชื่อไม่มีสาขาของวารสารนั้น ให้เลือกจาก 3 ค่านี้: `วิทยาศาสตร์และเทคโนโลยี` · `วิทยาศาสตร์สุขภาพ` · `มนุษยศาสตร์และสังคมศาสตร์` โดยดูจากขอบเขตของวารสาร (aims & scope) และบันทึกว่าเลือกเอง
- วารสารที่ครอบคลุมหลายสาขา: เลือกสาขาที่บทความส่วนใหญ่อยู่

**คอลัมน์อื่น:**
- **`name_th`, `name_en`:** ตามหน้าปกหรือเว็บไซต์ของวารสาร
- **`issn`, `eissn`:** รูป `NNNN-NNNN`
- **`publisher_org`:** สถาบันหรือสมาคมเจ้าของวารสาร (ชื่อเต็มภาษาไทย)
- **`url`:** หน้าแรกของวารสาร

### 11.2 `institutions_aliases.csv`: รวมชื่อสถาบัน

คอลัมน์เดียวกับ [`example/institutions_aliases.csv`](example/institutions_aliases.csv):

```
alias,inst_id,name_th,name_en,type,province,country,ror
มหาวิทยาลัยนเรศวร,nu,มหาวิทยาลัยนเรศวร,Naresuan University,university,TH-65,TH,
Naresuan University,nu,,,,,,
```

- **1 แถว = 1 ชื่อเรียก (`alias`):** ชื่อที่พบในสังกัด เช่น ชื่อไทย ชื่ออังกฤษ ชื่อย่อ หรือชื่อวิทยาเขต
  - ระบบจับคู่เมื่อชื่อนี้ **ปรากฏอยู่ในข้อความสังกัด** (ไม่สนตัวพิมพ์ ช่องว่าง วรรณยุกต์ และเครื่องหมาย) ดังนั้น `มหาวิทยาลัยนเรศวร` จับ "คณะบริหารธุรกิจ มหาวิทยาลัยนเรศวร" ได้เอง
  - ชื่อเรียกต้องยาวอย่างน้อย 4 ตัวอักษร และห้ามซ้ำกัน ชื่อย่อสั้น ๆ เช่น "มน." ใช้ไม่ได้ เพราะกำกวม
- **`inst_id`:** รหัสสถาบัน ใช้ตัวเล็ก a–z, 0–9 และ `-` ยาว 2–41 ตัว เช่น `nu`, `cmu`, `kku`, `chula`
  - ใช้ชื่อย่อภาษาอังกฤษที่สถาบันใช้เอง ถ้าชนกัน เติมจังหวัดหรือคำขยาย เช่น `rmutl`, `crru`
  - **ห้ามเปลี่ยนรหัสที่เคยใช้แล้ว** (ลิงก์หน้าสถาบันบนเว็บผูกกับรหัสนี้)
- **แถวแรกของแต่ละ `inst_id`:** ใส่ `name_th`, `name_en`, `type`, `province`, `country` ให้ครบ แถวต่อ ๆ ไปของรหัสเดียวกันเว้นว่างได้
- **`type` เลือก 1 ค่า:** `university` · `rajabhat` · `rajamangala` · `hospital` · `government` · `research` · `company` · `other`
- **`province`:** ที่ตั้งวิทยาเขตหลัก รูป `TH-xx` สถาบันต่างประเทศเว้นว่าง
- **`country`:** รหัส 2 ตัว เช่น `TH`, `JP`
- **`ror`:** ถ้าหาเจอที่ ror.org

**หลักการรวม (ตัดสินเองได้ แต่ต้องใช้หลักเดียวกันทั้งไฟล์):**

1. **ระดับที่รวม = มหาวิทยาลัยหรือหน่วยงานแม่:** คณะ ภาควิชา ศูนย์ และสถาบันวิจัยในมหาวิทยาลัย นับเป็นของมหาวิทยาลัย
2. **วิทยาเขต:**
   - มหาวิทยาลัยเดียวที่มีหลายวิทยาเขต (เช่น ราชมงคลล้านนา น่าน) นับเป็นมหาวิทยาลัยเดียว
   - ราชภัฏแต่ละแห่งเป็นสถาบันแยกกัน
3. **โรงพยาบาลของคณะแพทย์:** (เช่น ศิริราช รามาธิบดี) นับเป็นของมหาวิทยาลัย
4. **โรงพยาบาลของกระทรวงสาธารณสุข:** แต่ละแห่งเป็นสถาบันแยก (`type: hospital`)
5. **หน่วยงานรัฐ:** รวมระดับกรม เช่น "กรมวิชาการเกษตร" ส่วนสำนักงานเขตพื้นที่การศึกษาแต่ละเขตเป็นสถาบันแยก (`government`)
6. **โรงเรียน:** แต่ละโรงเรียนเป็นสถาบันแยก (`type: other`)
7. **มหาวิทยาลัยที่เปลี่ยนชื่อ:** ใช้ `inst_id` เดียว แล้วใส่ชื่อเก่าเป็นชื่อเรียกเพิ่ม

**ทำอย่างไรให้เร็ว:**
- `atlas profile --aliases-todo aliases_todo.csv` (หัวข้อ 12) ได้ไฟล์ **สังกัดที่พบบ่อยที่สุด 300 อันดับที่ยังไม่มีในตาราง** เรียงตามจำนวนบทความ
- ไล่เติมจากบนลงล่าง โดยเติม `inst_id` และข้อมูลอื่น แล้วคัดลอกแถวไปต่อท้าย `institutions_aliases.csv` (ไม่ต้องคัดลอกคอลัมน์ `articles`)
- รัน `atlas profile` ซ้ำ ทำวนไปจน **"ครอบคลุมแถวสังกัด" ≥ 80%** (ถึง 90% ยิ่งดี)

## 12. ติดตั้งและตรวจไฟล์เองด้วย `atlas profile` (ทีละขั้น)

ทำครั้งแรกครั้งเดียว ใช้เวลาประมาณ 15 นาที ตัวอย่างนี้ใช้ Windows ส่วน macOS และ Linux ใช้คำสั่งเดียวกันใน Terminal

1. **ติดตั้ง Git:** <https://git-scm.com/download/win> (กด Next จนจบ)
2. **ติดตั้ง uv:** ตัวจัดการ Python ไม่ต้องลง Python เอง เปิด PowerShell แล้ววาง:
   ```powershell
   powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
   ```
   ติดตั้งเสร็จแล้วปิดและเปิด PowerShell ใหม่
3. **ดาวน์โหลดโปรเจกต์:**
   ```powershell
   cd D:\
   git clone https://github.com/santipongth/tci-research-atlas.git
   cd tci-research-atlas\pipeline
   uv sync
   ```
   `uv sync` ครั้งแรกใช้เวลาไม่กี่นาที ระบบดาวน์โหลด Python และไลบรารีให้เอง
4. **ทดลองกับตัวอย่าง:** ถ้าเห็น `[profile] OK — nothing to fix` แปลว่าติดตั้งถูกต้อง
   ```powershell
   uv run atlas profile ..\docs\corpus\example
   ```
5. **ตรวจคลังของเรา** (ทำซ้ำทุกครั้งที่แก้ไฟล์):
   ```powershell
   uv run atlas profile D:\atlas-data\corpus\2026Q4 --md D:\atlas-data\profile.md --aliases-todo D:\atlas-data\aliases_todo.csv
   ```
6. **อ่านผล:** เปิด `profile.md` (Notepad หรือ VS Code)
   - **"ต้องแก้ก่อนส่ง"** (ท้ายรายงาน): ต้องไม่มีรายการเหลือ คำสั่งจะจบด้วย `[profile] OK — nothing to fix`
   - **"Files with errors":** บรรทัดที่ผิดพร้อม `ไฟล์:บรรทัด` และเหตุผล ไปแก้ที่ต้นทาง แล้วสร้างไฟล์ใหม่
   - **"Corpus format 1.0":** % ความครบของแต่ละช่อง และรหัสบทความมาจากไหน
   - **"ความครบถ้วนของ metadata":** % ของบทคัดย่อ คำสำคัญ และ DOI
   - **"Articles per year":** ยอดต่อปี ปีที่ยอดตกฮวบมักแปลว่าดึงข้อมูลไม่ครบ
   - **"Companion files":** ปัญหาของ `journals.csv` และไฟล์อื่น พร้อม % ที่ `institutions_aliases.csv` ครอบคลุม
7. **อัปเดตคู่มือและโปรแกรมเป็นรุ่นล่าสุด** (ทำก่อนเริ่มงานทุกสัปดาห์):
   ```powershell
   cd D:\tci-research-atlas
   git pull
   cd pipeline
   uv sync
   ```

**ห้าม** `git push` หรือ commit ไฟล์ข้อมูลใด ๆ เข้า repo นี้ repo นี้เป็น public ใครก็เปิดดูได้ ถ้าต้องเขียนสคริปต์ทำความสะอาดข้อมูล ให้เก็บนอกโฟลเดอร์ `tci-research-atlas` หรือใน repo ส่วนตัวแบบ private

### 13.1 ตารางเทียบค่าที่พบบ่อย

**`article_type`: ดูจากชื่อหมวดในสารบัญหรือประเภทบทความในต้นฉบับ**

| ในต้นฉบับ | ใส่ |
|---|---|
| บทความวิจัย, Research Article, Original Article | `research-article` |
| บทความปริทัศน์, บทความทบทวนวรรณกรรม, Review Article | `review-article` |
| บทความวิชาการ, Academic Article | `academic-article` |
| รายงานผู้ป่วย, กรณีศึกษา, Case Report | `case-report` |
| บทความสั้น, Short Communication, Brief Report | `short-communication` |
| บทวิจารณ์หนังสือ, Book Review | `book-review` |
| บทบรรณาธิการ, Editorial, Editor's Note | `editorial` |
| คำแก้, ประกาศแก้ไข, Erratum, Corrigendum | `erratum` |
| ไม่มีระบุ | ไม่ใส่ช่องนี้ |
| ระบุไว้ แต่ไม่ตรงกับแถวใดในตาราง | `other` |

**`role`: ดูจากคำนำหน้าหรือคำบรรยายใต้ชื่อผู้แต่ง** แล้วตัดคำนำหน้าออกจาก `name` เสมอ

| ในต้นฉบับ | ใส่ |
|---|---|
| ศ. / รศ. / ผศ. / อ. / ดร. (ที่เป็นอาจารย์), Professor, Lecturer | `lecturer` |
| นักวิจัย, Researcher | `researcher` |
| นักศึกษาปริญญาโท, นิสิตปริญญาโท, Master's student | `student-master` |
| นักศึกษาปริญญาเอก, นิสิตปริญญาเอก, Ph.D. student | `student-doctoral` |
| นักศึกษา, นิสิต (ไม่ระบุระดับ) | `student` |
| อาชีพอื่น เช่น พยาบาล ครู | `other` |
| ไม่ระบุ | ไม่ใส่ช่องนี้ |
